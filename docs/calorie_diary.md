# 칼로리 다이어리 기능 문서

## 1. 문서 목적

이 문서는 HealthLog 프로젝트의 **칼로리 다이어리(Calorie Diary)** 기능 구현 기준을 정리한다.

사용자가 선택한 날짜를 기준으로 식단(섭취)과 운동(소모) 기록을 입력·저장하고, 저장된 기록을 조회·수정·삭제하며 하루 동안의 총 섭취 칼로리, 총 소모 칼로리, 순 칼로리를 계산하는 것을 목적으로 한다.

> 참고: 이 문서는 구현 전 명세 초안이다. 메인 화면의 날짜 선택 방식과 CSV 파일 저장 경로는 팀의 공통 설계와 확인한 뒤 최종 확정한다.

## 2. 기능 범위 및 주요 할 일

이 기능은 다음 세 가지 핵심 기능을 담당한다.

1. **식단·운동 기록 입력 및 저장**
   - 식단 또는 운동 구분 선택
   - 기록 이름 입력
   - 칼로리 입력
   - 선택 날짜와 함께 CSV 파일에 저장

2. **칼로리 기록 조회·수정·삭제**
   - 선택한 날짜의 기록 목록 조회
   - 기존 기록의 이름 및 칼로리 수정
   - 선택한 기록 삭제

3. **일일 칼로리 계산 및 날짜 연동**
   - 선택 날짜의 식단 기록을 섭취 칼로리로 합산
   - 선택 날짜의 운동 기록을 소모 칼로리로 합산
   - 순 칼로리 계산
   - 메인 화면에서 선택된 날짜와 연동

## 3. 데이터 및 연동 기준

### 3.1 저장 데이터 (CSV)

칼로리 기록은 다음 형식을 기준으로 한다.

| **컬럼** | **설명** | **예시** |
| --- | --- | --- |
| date | 기록 날짜 (`YYYY-MM-DD`) | 2026-10-29 |
| type | 기록 종류 (`intake`: 섭취, `burn`: 소모) | intake |
| name | 음식 또는 운동 이름 | 닭가슴살 |
| kcal | 칼로리 (정수) | 200 |

CSV 저장 예시:

```csv
date,type,name,kcal
2026-10-29,intake,닭가슴살,200
2026-10-29,burn,러닝,300
```

- 화면에서는 사용자가 이해하기 쉽도록 `식단 / 운동`으로 표시한다.
- CSV 저장 시 식단은 `intake`, 운동은 `burn`으로 저장하는 방식을 기준으로 한다.
- 파일 인코딩은 UTF-8(BOM 허용)을 기준으로 한다.

### 3.2 날짜 데이터 연동

- 메인 화면의 달력에서 선택된 날짜(`selected_date`)를 전달받는다.
- 날짜 형식은 `YYYY-MM-DD`를 사용한다.
- 전달받은 날짜를 기준으로 해당 날짜의 기록만 조회하고 계산한다.
- 날짜가 변경되면 칼로리 다이어리 화면의 기록 목록과 계산 결과도 갱신한다.

## 4. 함수 구성

### 4.1 `add_record(date, record_type, name, kcal)`

식단 또는 운동 기록을 입력받아 저장한다.

**입력값**
- `date`: 기록 날짜
- `record_type`: 식단 또는 운동 구분
- `name`: 음식 또는 운동 이름
- `kcal`: 칼로리

**주요 동작**
- 입력값 확인
- 기록 종류 변환 (`식단 → intake`, `운동 → burn`)
- CSV 파일에 기록 추가

### 4.2 `manage_record(records)`

저장된 칼로리 기록을 조회하고 수정하거나 삭제한다.

**입력값**
- `records`: 선택 날짜의 칼로리 기록 목록

**주요 동작**
- 저장된 기록 목록 출력
- 선택한 기록 수정
- 선택한 기록 삭제
- 변경 결과 CSV 반영

### 4.3 `calculate_calorie(records)`

선택 날짜의 칼로리 기록을 기준으로 하루 칼로리를 계산한다.

**입력값**
- `records`: 선택 날짜의 칼로리 기록 목록

**계산 결과**
- 총 섭취 칼로리
- 총 소모 칼로리
- 순 칼로리

## 5. 계산 기준

| **항목** | **계산 방식** |
| --- | --- |
| 총 섭취 | 해당 날짜 `intake` 기록의 kcal 합계 |
| 총 소모 | 해당 날짜 `burn` 기록의 kcal 합계 |
| 순 칼로리 | 총 섭취 - 총 소모 |

예시:

- 총 섭취: 1,800 kcal
- 총 소모: 400 kcal
- 순 칼로리: 1,400 kcal

## 6. 입력값 및 예외 처리 규칙

| **항목** | **검증 및 처리 규칙** |
| --- | --- |
| 기록 종류 | 식단 또는 운동 중 하나를 선택 |
| 기록 이름 | 빈 값은 저장하지 않음 |
| 칼로리 | 0 이상의 숫자만 입력 가능 |
| 날짜 | `YYYY-MM-DD` 형식의 유효한 날짜인지 확인 |
| CSV 파일 없음 | 새 파일을 생성하고 저장 시작 |
| 해당 날짜 기록 없음 | 빈 목록 및 칼로리 0으로 표시 |
| 잘못된 CSV 데이터 | 해당 행을 제외하고 프로그램은 계속 실행 |

## 7. GUI 구성 기준

칼로리 다이어리 화면은 다음 항목으로 구성한다.

- 현재 선택 날짜 표시
- 식단 / 운동 선택
- 음식 또는 운동 이름 입력창
- 칼로리 입력창
- 기록 추가 버튼
- 선택 날짜의 기록 목록
- 기록 수정 버튼
- 기록 삭제 버튼
- 총 섭취 칼로리 표시
- 총 소모 칼로리 표시
- 순 칼로리 표시

## 8. 다른 기능과의 연동

### 메인 화면 / 달력

- 메인 화면에서 선택된 날짜를 전달받는다.
- 선택 날짜가 변경되면 해당 날짜의 칼로리 기록을 표시한다.

### 주간 건강 리포트

- 칼로리 다이어리에서 저장한 CSV 데이터를 주간 건강 리포트 기능에서 사용한다.
- `intake` 기록은 섭취 칼로리, `burn` 기록은 소모 칼로리로 집계한다.

## 9. 완료 조건 (Acceptance Criteria)

- 식단 또는 운동을 선택하여 기록을 입력할 수 있다.
- 기록 이름과 칼로리를 입력하여 CSV 파일에 저장할 수 있다.
- 선택한 날짜의 기록만 조회된다.
- 기존 기록을 수정할 수 있다.
- 기존 기록을 삭제할 수 있다.
- 총 섭취 칼로리가 정확히 계산된다.
- 총 소모 칼로리가 정확히 계산된다.
- 순 칼로리가 `섭취 - 소모` 방식으로 정확히 계산된다.
- 메인 화면에서 선택된 날짜와 연동된다.
- 기록이 없거나 CSV 파일이 없어도 프로그램이 종료되지 않는다.
- 문서가 `docs/calorie_diary.md` 경로에 저장되어 있다.
