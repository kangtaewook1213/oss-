# 인바디 기능 명세 및 CSV 데이터 형식

## 1. 문서 목적

이 문서는 HealthLog 프로젝트의 **인바디 수치 입력 및 저장, BMI 자동 계산, 이전 기록 비교** 기능을 구현하기 위한 기준을 정리한다. 입력 항목, CSV 저장 구조, 계산 방법, 입력값 검증 규칙을 미리 정의하여 팀원 간 데이터 형식을 통일하고 구현 과정에서 발생할 수 있는 혼선을 줄이는 것을 목적으로 한다.

> 참고: 이 문서는 구현 전 명세 초안이다. CSV 파일명, 공통 데이터 구조, GUI와의 연동 방식은 팀의 공통 설계와 확인한 뒤 확정한다.

## 2. 기능 범위

이 문서는 다음 기능을 다룬다.

1. 날짜별 신체 정보 입력 및 저장
2. 키와 체중을 이용한 BMI 계산
3. 현재 기록과 이전 기록의 변화량 비교
4. 입력값 검증 및 오류 안내

## 3. 입력 항목

| 항목 | 필수 여부 | 형식 | 설명 |
|---|---|---|---|
| 날짜 | 필수 | `YYYY-MM-DD` 형식의 문자열 | 기록을 구분하는 날짜 |
| 키 | 필수 | 양의 숫자, cm 단위 | BMI 계산에 사용 |
| 체중 | 필수 | 양의 숫자, kg 단위 | BMI 계산 및 기록 비교에 사용 |
| 골격근량 | 선택 | 양의 숫자, kg 단위 | 기록 및 이전 값 비교에 사용 |
| 체지방률 | 선택 | 0 이상 100 이하의 숫자, % 단위 | 기록 및 이전 값 비교에 사용 |
| BMI | 자동 계산 | 소수점 둘째 자리까지 표시 | 키와 체중을 바탕으로 계산 |

- 키는 BMI 계산에 필요하므로 입력 항목에 포함한다.
- 골격근량과 체지방률은 측정 장비나 사용 상황에 따라 입력하지 않을 수 있으므로 선택 항목으로 둔다.
- BMI는 사용자가 직접 입력하지 않고 프로그램이 계산한다.
- 저장 시에는 계산 전 입력값과 계산 결과를 구분해 관리한다.

## 4. CSV 데이터 저장 형식

### 4.1 권장 열 구성

CSV 한 행은 날짜별 신체 기록 한 건을 의미한다.

```csv
date,height_cm,weight_kg,skeletal_muscle_kg,body_fat_percent,bmi
2026-10-12,170.0,65.2,28.4,22.1,22.56
```

위 행은 **형식 예시용 가상 데이터**이며 실제 측정값이 아니다.

| 열 이름 | 데이터 형식 | 설명 |
|---|---|---|
| `date` | 문자열 | 기록 날짜 (`YYYY-MM-DD`) |
| `height_cm` | 숫자 | 키(cm) |
| `weight_kg` | 숫자 | 체중(kg) |
| `skeletal_muscle_kg` | 숫자 또는 빈 값 | 골격근량(kg) |
| `body_fat_percent` | 숫자 또는 빈 값 | 체지방률(%) |
| `bmi` | 숫자 | 프로그램에서 계산한 BMI |

### 4.2 저장 규칙

- CSV 첫 행에는 열 이름을 기록한다.
- 날짜는 `YYYY-MM-DD` 형식으로 저장한다.
- 숫자는 문자열 단위나 단위를 붙이지 않고 숫자 값으로 저장한다. 예: `65.2`
- 선택 항목을 입력하지 않았다면 해당 셀은 빈 값으로 저장한다.
- BMI는 키와 체중을 바탕으로 계산한 값을 저장한다.
- CSV 파일명과 저장 위치는 프로젝트의 공통 저장 규칙이 정해지면 팀원들과 맞춘다.
- 같은 날짜에 여러 기록을 허용할지, 날짜당 한 건만 허용할지는 구현 전에 팀에서 결정한다.

## 5. BMI 계산 기준

BMI(체질량지수)는 체중(kg)을 키(m)의 제곱으로 나누어 계산한다.

\[
BMI = \frac{체중(kg)}{키(m)^2}
\]

키를 cm로 입력받는 경우 m 단위로 변환한 후 계산한다.

```python
height_m = height_cm / 100
bmi = weight_kg / (height_m ** 2)
bmi = round(bmi, 2)
```

- 키와 체중이 유효한 숫자이고 0보다 클 때만 계산한다.
- 화면에는 소수점 둘째 자리까지 표시한다.
- BMI는 참고용 수치이며, 이 프로젝트에서는 의학적 진단이나 건강 상태 판정에 사용하지 않는다.

## 6. 이전 기록 비교 기준

현재 기록과 날짜상 가장 가까운 이전 기록을 비교 대상으로 삼는 것을 기본안으로 한다. 다만 같은 날짜의 기록을 여러 건 허용하는지에 따라 세부 규칙은 달라질 수 있다.

### 6.1 변화량 계산

각 항목의 변화량은 다음과 같이 계산한다.

```python
change = current_value - previous_value
```

- 양수(+)는 이전 기록보다 수치가 증가했음을 의미한다.
- 음수(-)는 이전 기록보다 수치가 감소했음을 의미한다.
- 0은 변화가 없음을 의미한다.
- 현재 또는 이전 값이 비어 있으면 해당 항목의 변화량은 계산하지 않는다.

### 6.2 화면 표시 예시

| 항목 | 이전 기록 | 현재 기록 | 변화량 |
|---|---:|---:|---:|
| 체중 | 65.5 kg | 65.2 kg | -0.3 kg |
| 골격근량 | 28.2 kg | 28.4 kg | +0.2 kg |
| 체지방률 | 22.5% | 22.1% | -0.4%p |

위 수치는 **표시 형식을 설명하기 위한 가상 예시**다. 체지방률처럼 퍼센트로 표시되는 값의 차이는 혼동을 줄이기 위해 퍼센트 변화율과 구분하여 **퍼센트포인트(%p)**로 표시한다.

## 7. 입력값 검증 규칙

| 항목 | 검증 규칙 | 처리 |
|---|---|---|
| 날짜 | `YYYY-MM-DD` 형식이며 실제 존재하는 날짜인지 확인 | 잘못된 날짜는 저장하지 않고 안내 |
| 키 | 숫자이며 0보다 큰지 확인 | 잘못된 값은 저장하지 않고 안내 |
| 체중 | 숫자이며 0보다 큰지 확인 | 잘못된 값은 저장하지 않고 안내 |
| 골격근량 | 입력했다면 숫자이며 0보다 큰지 확인 | 잘못된 값은 저장하지 않고 안내 |
| 체지방률 | 입력했다면 숫자이며 0 이상 100 이하인지 확인 | 범위를 벗어나면 저장하지 않고 안내 |
| BMI | 키와 체중이 유효할 때만 계산 | 유효하지 않으면 계산하지 않고 입력 오류 안내 |

추가 규칙:

- 필수 항목이 비어 있으면 저장하지 않는다.
- 숫자 입력란에 문자나 기호 등 숫자로 변환할 수 없는 값이 입력되면 오류 메시지를 표시한다.
- 오류가 발생했을 때 프로그램이 비정상 종료되지 않도록 처리한다.
- 소수점 입력은 허용한다.

## 8. 문서 및 구현 완료 조건

이 문서의 작업은 다음 조건을 충족하면 완료된 것으로 본다.

- [ ] 날짜, 키, 체중, 골격근량, 체지방률 입력 항목이 정의되어 있다.
- [ ] CSV 열 이름과 각 열의 의미가 정의되어 있다.
- [ ] BMI 계산 공식과 표시 자릿수가 정의되어 있다.
- [ ] 이전 기록 비교 및 변화량 표시 규칙이 정의되어 있다.
- [ ] 필수 입력값과 숫자 범위 검증 규칙이 정의되어 있다.
- [ ] 문서가 `docs/body-tracker.md` 경로에 저장되어 있다.
- [ ] 팀의 공통 데이터 저장 방식과 충돌하는 부분이 없는지 확인했다.

## 9. 팀 확인이 필요한 사항

아래 항목은 팀의 기존 설계와 맞춰 최종 확정한다.

1. 실제 CSV 파일명과 저장 폴더
2. 날짜당 기록을 한 건만 허용할지 여부
3. 선택 항목(골격근량, 체지방률)의 빈 값 저장 방식
4. 공통 GUI와 데이터 구조에서 사용할 변수 및 열 이름
5. CSV 문자 인코딩과 데이터 읽기·쓰기 담당 모듈

이 문서는 구현을 시작하기 위한 기준안이며, 팀에서 결정한 사항이 있으면 해당 결정에 맞게 갱신한다.
