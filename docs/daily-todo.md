# 메인 화면 GUI 및 캘린더 날짜 선택 기능 명세

## 1. 문서 목적

이 문서는 HealthLog 프로젝트의 **프로그램 메인 화면 GUI 구현, 달력(Calendar) 관리, 날짜 선택 감지 및 시스템 글로벌 데이터 캐스팅 파이프라인 구축**을 위한 기준을 정리한다. 선택된 날짜 정보를 타 서브 모듈(칼로리 다이어리, 데일리 To-do, 인바디 트래커 등)로 정확히 전달하는 것을 목적으로 한다.

> 참고: 이 문서는 구현 전 명세 초안이다. 공통 GUI 레이아웃 구조와 파이프라인 인터페이스는 팀의 공통 설계와 확인한 뒤 확정한다.

## 2. 기능 범위 및 주요 할 일

이 문서는 다음 핵심 기능을 다룬다.

1. **메인 화면 관리 (Calendar GUI):** 메인 화면 레이아웃 구성 및 달력 위젯배치
2. **연도 및 월 이동:** 달력 내 이전/다음 달, 연도 이동 기능
3. **날짜 선택 감지 및 상태 관리:** 사용자 클릭에 따른 선택 날짜(`YYYY-MM-DD`) 상태 관리
4. **캐스팅 파이프라인 구축:** 선택된 날짜 데이터를 타 기능(칼로리, To-do, 신체 트래커 등)으로 전파하는 데이터 파이프라인 구현
5. **날짜별 기록 존재 여부 표시:** 기록(식단/운동 등)이 있는 날짜에 점(Dot) 또는 색상으로 마커 표시

## 3. 데이터 파이프라인 및 연동 기준

### 3.1 날짜 데이터 인터페이스
- **기본 날짜 형식:** `YYYY-MM-DD` (예: `2026-10-12`)
- **전용 이벤트 감지:** 달력 선택 이벤트(`<<CalendarSelected>>`) 발생 시 핸들러 호출

### 3.2 캐스팅 파이프라인 동작 방식
- 사용자가 달력에서 특정 날짜를 클릭하면 전역 상태 변수(`selected_date`)가 즉시 업데이트된다.
- 파이프라인 함수(`dispatch_data_pipeline`)가 호출되어 연동된 각 서브 모듈로 선택된 날짜 정보를 전달한다.
- 각 서브 모듈은 전달받은 날짜 정보를 기반으로 해당 날짜의 데이터를 화면에 렌더링한다.

## 4. 기록 마커 표시 규칙

- 날짜별 데이터(식단, 운동, To-do 등)의 존재 여부를 조회한다.
- 기록이 존재하는 날짜의 캘린더 날짜 셀에 배경색 변경 또는 마커 태그(예: `has_record`)를 적용하여 시각적으로 표시한다.

## 5. 입력값 및 예외 처리 규칙

| 항목 | 검증 및 처리 규칙 |
|---|---|
| 날짜 선택 | `YYYY-MM-DD` 형식의 유효한 날짜인지 확인 및 전역 상태 갱신 |
| 파이프라인 호출 | 연동된 모듈이 없을 경우 예외 발생 없이 로그 출력 후 대기 |
| 마커 로딩 | 데이터가 없거나 로딩 실패 시 기본 달력 스타일 유지 |

## 6. 완료 조건 (Acceptance Criteria)

- [ ] 원하는 날짜를 선택하면 해당 날짜가 정상적으로 선택/표시된다.
- [ ] 선택된 날짜 정보가 캐스팅 파이프라인을 통해 다른 기능(서브 모듈)으로 전달되어 해당 날짜의 뷰가 출력된다.
- [ ] 달력에서 이전/다음 달 이동이 정상 동작한다.
- [ ] 기록이 존재하는 날짜에 마커(색상/점)가 정상 표시된다.
- [ ] 문서가 `docs/main-calendar.md` (또는 지정 경로)에 저장되어 있다.
